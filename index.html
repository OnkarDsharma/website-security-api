Inspection Vectors

What we check

Each scan evaluates 10 security checks and explains findings in actionable developer terms.

01

Security Headers

Validates Strict-Transport-Security (HSTS), Content-Security-Policy (CSP), X-Frame-Options, X-Content-Type-Options, and Referrer-Policy.

02

SSL / TLS Certificate

Audits certificate expiration dates, trust chains, hostname mismatches, and deprecated protocol versions (TLS 1.0 / 1.1).

03

Exposed Sensitive Files

Scans for accidentally exposed .env files, .git/config repositories, AWS credentials, and database backups.

04

CMS Version Fingerprints

Detects WordPress, Joomla, and Drupal installations to flag outdated versions vulnerable to known exploit vectors.

05

Server Info Leakage

Identifies overly descriptive Server and X-Powered-By response headers that leak exact software builds to attackers.

06

Email Spoofing (SPF & DMARC)

Queries DNS records to verify whether the domain has properly configured SPF and DMARC policies to prevent email impersonation.

07

CORS Misconfiguration

Flags dangerous Cross-Origin Resource Sharing combinations, such as wildcard origins paired with credential transmission.

08

Cookie Security Flags

Audits Set-Cookie headers for missing Secure, HttpOnly, and appropriate SameSite protection flags.

09

Mixed Content Ingestion

Detects insecure unencrypted HTTP assets (scripts, stylesheets, images) embedded inside secure HTTPS pages.

10

Open Redirect Vulnerabilities

Tests common redirect parameter names for unvalidated forwarding that could be weaponized in phishing campaigns.

A note on accuracy. This is an automated, lightweight scanner, not a substitute for a comprehensive penetration test or manual audit. CMS checks use lightweight version heuristics, not a live CVE vulnerability scanner. If any check cannot be completed due to firewall or region blocks, the report explicitly states so rather than showing a false clean status.
